# 失敗の記録

新しいものを下に追記する。

## 2026-10-25 OpenRailwayMap のタイルが 403 になる
- **起きたこと**: 計画で使う予定だった `https://{s}.tiles.openrailwaymap.org/standard/{z}/{x}/{y}.png` が 403（アクセス拒否）を返した。
- **原因**: 運営側の配信方式と利用規約が変わっていた。計画を立てる段階で、URL が実際に使えるかを確かめていなかった。
- **学び**: 外部 API やタイルに頼る設計は、計画の段階で実際にアクセスして確かめる。旅行中に使うものは、外部依存を減らすほうが安全。

## 2026-10-25 TS7053: react-leaflet の style 関数で any 型エラー
- **起きたこと**: `<GeoJSON style={(feature) => RAIL_STYLES[feature.properties.kind]}>` が `npm run build` で型エラーになった。
- **原因**: react-leaflet は feature の `properties` を `any` 型として渡す。`any` の値はオブジェクトのキーとして使えない（TS7053）。
- **対処**: `feature!.properties as RailLineProps` のように、自前の型を明示した。
- **学び**: ライブラリから受け取る値の型は、そのライブラリの型定義で決まる。自分のデータの型が自動で付くとは限らない。

## 2026-10-26 CARTO の背景タイルが API キー必須になっていた
- **起きたこと**: キーなしの URL にアクセスすると、地図ではなく「API KEY REQUIRED」の透かしタイルが返った。
- **原因**: CARTO の規約が 2026-09-29 付で変わっていた。選定時に「キーが要らない」と判断したあと、実際のタイルの中身を確かめていなかった。
- **対処**: 無料キーを取得し、環境変数 `VITE_CARTO_API_KEY` で渡す。
- **学び**: HTTP ステータスが 200 でも中身が使えるとは限らない。外部タイルは画像を実際に見て確認する。OpenRailwayMap のとき（403）と同じ「外部依存を確かめていなかった」失敗の繰り返し。
